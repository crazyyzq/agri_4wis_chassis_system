# 整车温柔调试记录 2026-07-07

## 调试原则

- 先单轮、低速、低加速度确认，再进入多轮同步。
- 每次测试必须保存原始日志目录，并记录摘要结论。
- 出现 EMCY、0x2183 故障锁存非零、尖锐异响、明显冲击或无法停稳时，立即停止继续升速。
- 本轮 0x6083/0x6084 profile acceleration / deceleration 按 `count/s^2` 使用；`50 rps^2 = 500000 count/s^2`。当前测试采用更保守的 `200000 count/s^2`。

- 行走轮悬空，允许做低速空载测试。

### BC2 插补必须遵守的状态机

BC2 在 Operation Enabled 状态下写插补缓存清除对象，SDO 可能成功应答但旧轨迹仍未真正清除。实测安全顺序为：

1. `0x6040 = 0x0006`，退出 Operation Enabled，但不复位驱动器、不改变绝对零点。
2. 配置 mode7、20 ms 插补周期和固定周期子模式 `0x60C0 = 0`。当前RPDO2只映射 `0x60C1:01` 位置点，不携带 `0x60C1:02` 时间值，因此不能使用要求逐点时间数据的 `-1` 子模式。
3. `0x60C4:06 = 0` 清除插补缓存。
4. 按 `0x0007 -> 0x000F` 恢复 Operation Enabled。
5. 四轴各预装 3 个静止RPDO2位置点，并在每组四轴点之后发送一次公共SYNC。
6. 四轴通过同步 RPDO1 发送 mode7 和 `0x003F`，再发送公共 SYNC 启动。
7. 运行中每 20 ms 发送一组四轴 RPDO2 点和一个公共 SYNC。

禁止在同一条连续缓存轨迹中直接由伸出切换为回收或由回收切换为伸出。实测这种直接反转会产生 `0x7390`。遥控方向改变时必须先完成上述退出使能、清缓存、重新预装和同步启动过程。中位命令也是主动停机命令，不能只停止发送新点而保留旧缓存。

## 2026-07-10 变轮距辅助与总线负载稳定性修复记录

- 现场故障：变轮距辅助电流偏小；右肩波轮回中 5 s 后转向开始回 0，此时再次拨动波轮，阀会立即打开且转向轴有概率进入不跟随状态。

- 归档说明：本条 `7/10 A` 参数已被 2026-07-14 悬空实测替代，当前值和保护逻辑以《遥控操作逻辑说明书》及 `ecu_config.h` 为准；本条只保留为历史调试证据。
- 固件侧反馈策略：实时控制只依赖 TPDO0 的实际位置/实际速度 freshness；TPDO1 的故障锁存、状态字和电流仍接收并使用，但不再要求 TPDO1 每个 SYNC 都 fresh 后才认为节点反馈可用。

## 2026-07-11 CAN2 Node1–8 偶发停止自恢复修复

- 根因一：节点仍保持 Operational 心跳但 TPDO0/TPDO1 停止时，旧逻辑不会进入节点恢复，历史“已就绪”状态可能长期残留。
- 根因二：四轮转向触发组发生部分发送失败后，`steer_group_degraded` 会永久锁存，只能依靠人工失能/再使能清除。
- 根因三：旧的传输恢复会重新挂起故障前的非零行走目标；节点恢复后存在重放过期速度命令的风险。
- 新恢复流程：500 ms 未收到必要的运动反馈即标记对应节点；先覆盖全部行走目标为零速且禁止使能，再通过CANopen服务发送 NMT Operational、清除 `0x2183` 锁存故障、CiA-402 fault reset、重新选择速度/位置模式并按 `0x0006 -> 0x0007 -> 0x000F` 重新使能。
- 恢复过程禁止 NMT reset-node/reset-communication，避免转向标定零点丢失。
- 节点反馈恢复后，必须先稳定 200 ms，再发送一组完整的 Node5–8 转向 arm/trigger 同步目标；只有该特定组完成后才解除行走联锁。任何故障前非零速度都不会自动重放，必须等待车辆任务发布新的有效命令快照。
- 串口 `[ECU CAN2 PDO]` 新增 `node_recover`、`stale`、`partial`、`steer_resync` 和 `partial_ok`，分别表示节点恢复掩码、反馈超时掩码、部分组恢复状态、转向重同步联锁和完成次数。
- 本次已通过185项静态契约测试并完成CPU0目标构建；仍需实车进行断开单节点反馈/制造短时CAN错误后的自动恢复验证，不能仅凭本地队列成功判定驱动器已经接受恢复命令。
