# 转向零点校准脚本说明

## 1. 目的

该脚本用于用 CAN 分析仪验证四个转向电机 Node5、Node6、Node7、Node8 的零点搜索流程，为后续 ECU 固件接入“三击 B1 启动找零模式”提供依据。

脚本默认不会发运动命令，必须显式传入 `--allow-motion`。脚本会保存校准结果。当前推荐方案不是写 `0x607C home offset`，也不复位驱动器，而是在机械中点位置直接写 `0x6064:00 = 0`。已知硬件行为是：写 `0x6064` 为 0 会把当前实际位置 count 清零，因此中点写零后该位置成为 0 点。

## 2. 当前实测稳定算法

1. 四个转向轴进入 CANopen Profile Velocity 模式。
2. 先向左极限运行，采用三段速度：
   - `|position| < 1,200,000 count`：`800000`；
   - `1,200,000 <= |position| < 1,650,000 count`：`250000`；
   - `|position| >= 1,650,000 count`：`60000`。
3. 通过 TPDO0/TPDO1 同时判断极限：
   - 实际电流绝对值达到 `900`，即 9A，立即判定并发零速；
   - 或者单方向行程超过 `1,500,000 count`，实际速度进入 `±30000` 窗口并持续 `300ms`，判定到达极限。
4. 不再使用 `15A` 作为硬判据；7.5A/15A 实测会让部分轴超时或过度顶死。
5. 四轴全部完成该方向极限后，统一反向脱离到内侧安全区：左极限后回到 `position <= +300000`，右极限后回到 `position >= -300000`。
6. 四轴全部完成左极限后，再按相同方法向右极限运行。
7. 左右极限都找到后，计算每轴中值：

```text
center = (left_limit + right_limit) / 2
```

8. 使用速度模式闭环回到各自中值位置，不使用 Profile Position 回中。实测在找限位之后直接用位置模式/RPDO1/SDO 位置命令，部分轴可能无故障但不执行目标位置。
9. 回中速度分三档：
   - 误差 `>300000 count`：`500000`；
   - 误差 `30000..300000 count`：`240000`；
   - 误差 `<30000 count`：`30000`。
10. 四轴均进入 `±2000 count` 并连续稳定 5 次后，才允许写 `0x6064:00 = 0`，使驱动器当前位置 count 清零。
11. 重新读取 `0x6064`，确认当前位置接近 0。
12. 可选执行 `0x1010:01 = 0x65766173` 保存驱动器参数。
13. 保存 `summary.json` 和 `steer_zero_calibration.json`。

## 3. 保存策略

默认保存到脚本输出目录：

```text
out/steer4_zero_calibration_YYYYMMDD_HHMMSS/
  events.json
  summary.json
  steer_zero_calibration.json
```

`steer_zero_calibration.json` 是给 ECU 后续导入/固化的文件，包含：

- `midpoint_counts_by_node`
- `left_limit_counts_by_node`
- `right_limit_counts_by_node`
- `span_counts_by_node`
- `set_current_position_zero_done`
- `position_counts_after_zero_write_by_node`

正式保存策略：

1. 找到左右机械极限；
2. 移动到左右极限中点；
3. 在该物理位置写 `0x6064:00 = 0`；
4. 读取 `0x6064`，确认当前位置接近 0；
5. 后续掉电重启后再次检查 `0x6064` 是否仍以当前上电位置为 0，且车辆机械转向没有被外力移动。

推荐使用：

```powershell
--set-current-position-zero
```

脚本默认的当前位置清零对象就是 `0x6064:00`：

```powershell
--set-current-position-zero `
--zero-object-index 0x6064 `
--zero-object-subindex 0 `
--zero-object-size 4 `
--zero-object-value 0 `
--save-drive-parameters
```

这会在移动到中点后写：

```text
0x6064:00 = 0
0x1010:01 = 0x65766173 ("save")
```

不采用 `0x607C home offset` 作为正式方案。原因是当前转向驱动器没有可靠绝对零点，单纯保存 offset 不能保证掉电重启后物理零位仍然安全有效。

## 4. 安全限制

- 必须显式加 `--allow-motion` 才会发运动命令。
- 电流保护阈值为 `900`，单位是 10mA，即 9A；达到即发零速。
- 主要极限判据是“最小行程 + 实际零速持续时间”，不是高电流。实测部分轴到机械端点后电流只有 0.2A 到 0.6A，等待高电流会导致超时。
- 实际速度进入 `±30000` 且持续 `300ms`，并且单向行程超过 `1,500,000 count`，才可认为到达极限。
- 每个方向默认超时 `20s`。
- 单方向最大行程默认 `1700000 count`，超过立即失败并发零速。
- 不发送 NMT reset，不做驱动器 reset。
- 任一轴出故障、超行程或超时，脚本会对四个转向轴发零速。

## 5. 推荐命令

CAN 分析仪 CAN1 接 ECU_CAN2/转向网络时，先 dry-run：

```powershell
python tools\canopen_position_debug\steer4_zero_calibration_debug.py
```

真实运动测试：

```powershell
python tools\canopen_position_debug\steer4_zero_calibration_debug.py `
  --bus can1 `
  --allow-motion `
  --left-sign 1 `
  --velocity-raw 800000 `
  --stall-immediate-current-10ma 900 `
  --max-travel-counts 3700000
```

如果发现“先向左”方向反了，只改 `--left-sign -1`，不要改脚本内部逻辑。

推荐找零并写 `0x6064=0` 清 count 的命令：

```powershell
python tools\canopen_position_debug\steer4_zero_calibration_debug.py `
  --bus can1 `
  --allow-motion `
  --left-sign 1 `
  --velocity-raw 800000 `
  --stall-immediate-current-10ma 900 `
  --max-travel-counts 3700000 `
  --set-current-position-zero `
  --save-drive-parameters
```

如果只想先验证清零动作，可以去掉 `--save-drive-parameters`，脚本仍会在写零后读取 `0x6064` 并记录结果。

## 6. ECU 后续接入建议

遥控器 B1 为 CH10。建议 ECU 侧后续增加独立 `steer_zero_calibration_fsm`，触发条件为：

1. 遥控在线；
2. 急停解除；
3. 高压与转向驱动器通信正常；
4. 车辆 P 档；
5. 油门最低；
6. HOME 不在液压/调节动作中；
7. B1 在限定时间内短按 3 次。

ECU 找零模式应独占 CAN2 转向输出，禁止行走速度输出。执行过程中必须持续监控：

- SBUS failsafe；
- 急停；
- CAN2 bus-off/tx timeout；
- Node5..8 TPDO0/TPDO1 新鲜度；
- `0x2183` 故障锁存；
- 实际电流；
- 实际位置行程；
- 每轴超时。

任一异常必须立即发四轴零速，并退出找零模式。不要通过驱动器 reset 恢复，因为 reset 可能破坏当前位置参考。

## 7. ECU 后续保存建议

ECU 后续接入时，建议按两级保护处理：

1. 正常情况：驱动器在机械中点写 `0x6064=0`，随后读取 `0x6064` 应接近 0。
2. 后续上电：如果车辆断电期间转向机构没有被外力推动，驱动器重新上电后仍应以当前物理位置为 0。
3. 保护校验：ECU 仍保存上次校准记录，包括左右极限跨度、中点、时间和校准状态。若掉电重启后 `0x6064`、行程窗口或反馈明显异常，禁止转向输出并提示重新校准。

## 8. 2026-07-10 实测结论

通过 CAN 分析仪在 Node5..8 上完成三段式找零验证，稳定通过的日志目录：

```text
out/steer_zero_three_stage_precise_20260710_173121
out/steer_zero_three_stage_refine_20260710_now
```

关键结果：

- 左极限峰值电流约 `9.06A..9.30A`；
- 右极限峰值电流约 `9.09A..9.33A`；
- 四轴均无故障锁存，状态字正常；
- 中点计算结果：
  - Node5: `-1571`
  - Node6: `245`
  - Node7: `-776`
  - Node8: `1274`
- 速度闭环回中最终误差：
  - Node5: `-1846 count`
  - Node6: `-2001 count`
  - Node7: `-1604 count`
  - Node8: `-1983 count`

结论：

1. `9A` 作为立即保护阈值合适；不要再等待 `15A`。
2. 找极限应三段降速，接近机械极限时必须慢速；当前更稳参数为 `800000 -> 250000 -> 60000`，降速点为 `1,200,000` 和 `1,650,000` count。
3. 高电流不是唯一可靠判据，必须使用“最小行程 + 实际零速持续”组合判据。
4. 找极限后必须先脱离内侧安全区，再切换方向或回中。
5. 回中使用速度闭环比位置模式更可靠。
6. 写 `0x6064=0` 前必须确认四轴已经进入小窗口，建议 `±2000 count`。
7. 若左右硬限位中点在机械上不是直行位置，不允许直接写 `0x6064=0`；必须先测出每个轮的机械直行偏置，再移动到“中点 + 偏置”后清零。
